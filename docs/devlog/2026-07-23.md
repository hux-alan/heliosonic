# Goal
Evaluate the scientific reasoning in Notebook 3 and determine whether the normalization decisions for ACE SWEPAM variables are justified before moving further toward sonification.

# Progress

## Data Quality
- Confirmed that proton density (Np) has the biggest data-quality problem, with about 64% invalid samples.
- Confirmed that solar wind speed (Vp) and proton temperature (Tpr) are mostly complete compared with Np.
- Decided that the main issue with Np is not just normalization, but the large amount of missing data.
- Agreed that gaps in Np should be preserved because interpolating or hiding them could make the measurements seem more continuous than they really are.

## Normalization Methods
- Compared min-max, robust percentile, z-score, and logarithmic min-max normalization.
- Interpreted each method as answering a different question rather than being simply good or bad.
- Clarified that the main risks are scientific interpretation risks:
    - min-max scaling can exaggerate small changes in Vp
    - linear min-max scaling can allow a few very hot Tpr values to dominate the sonification range
    - hiding gaps in Np could falsely imply continuous density observations
- Agreed with most of the notebook recommendations:
    - Np: robust percentile or min-max after preserving gaps
    - Vp: min-max for sonification, with z-scores still useful for statistical analysis
    - Tpr: logarithmic min-max because of the clearly right-skewed distribution
- Estimated that the Codex recommendations were about 90-95% correct, with only minor changes needed to wording and emphasis.

## Plotting Issue
- Found an important issue in the common valid samples plots.
- Noticed long diagonal lines connecting data segments that should probably be separated by missing observations.
- Determined that the plotting code is most likely using `times[common_mask]`, which removes invalid timestamps before plotting.
- This causes Matplotlib to connect the last valid point before a gap directly to the first valid point after the gap.
- Decided this creates a misleading visual impression of continuous evolution when simultaneous observations are actually missing.
- Identified the fix: keep the full time axis and replace invalid samples with NaN so Matplotlib breaks the line across missing intervals.
